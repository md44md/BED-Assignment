# Hayder Zikry

## Feature 1 - Officer Login / Logout

**User Story:** *As a NEA Officer, I would like to log in and out with my officer credentials, so that I could access inspection scheduling and logging features.*

**Endpoints under test:** `POST /officers/login`, `POST /officers/logout`

**Evidence:** Postman screenshots in [`screenshots/hayder-zikry/feature1-officer-auth/`](./screenshots/hayder-zikry/feature1-officer-auth/)

### Test cases

| # | Request                      | Expected                    | What it proves                                                             |
| - | ---------------------------- | --------------------------- | -------------------------------------------------------------------------- |
| 1 | Login - Success              | `200` + JWT token         | Valid officer credentials authenticate and receive a token                 |
| 2 | Login - Wrong Password       | `401` Invalid credentials | Wrong password is rejected                                                 |
| 3 | Login - Non-Officer Account  | `404` Account not found   | Login is role-isolated (a`customer` account cannot log in as an officer) |
| 4 | Login - Account Not Found    | `404` Account not found   | Unknown email is rejected                                                  |
| 5 | Login - Missing Password     | `400` validation error    | Joi validation blocks missing fields                                       |
| 6 | Login - Invalid Email Format | `400` validation error    | Joi validation blocks malformed email                                      |
| 7 | Logout - Success             | `200` logout message      | Stateless JWT logout confirms and client discards token                    |

Seeded officer credentials used for testing: `mary@email.com` / `Mary123!`

## Feature 2 - Log Inspection Result

**User Story:** *As a NEA Officer, I would like to log an inspection result with a score and remarks for a stall, so that I could maintain an auditable record of hygiene compliance.*

**Endpoint under test:** `POST /inspections` (NEA officer only, JWT-protected)

**Evidence:** Postman screenshots in [`screenshots/hayder-zikry/feature2-log-inspection/`](./screenshots/hayder-zikry/feature2-log-inspection/)

### Test cases

| # | Request                         | Expected                    | What it proves                                                 |
| - | ------------------------------- | --------------------------- | -------------------------------------------------------------- |
| 1 | Log Inspection - Success        | `201` + inspection record | Valid officer logs a score + remarks against an existing stall |
| 2 | Log Inspection - With Past Date | `201` + inspection record | Optional`inspectionDate` is accepted when supplied           |
| 3 | No Token                        | `401` Unauthorized        | Endpoint requires authentication                               |
| 4 | Customer Token (Wrong Role)     | `403` Forbidden           | Authorization is officer-only (a customer token is rejected)   |
| 5 | Missing Score                   | `400` validation error    | Joi requires`score`                                          |
| 6 | Score Above 100                 | `400` validation error    | Score range 0-100 is enforced                                  |
| 7 | Empty Remarks                   | `400` validation error    | Remarks cannot be empty                                        |
| 8 | Future Inspection Date          | `400` validation error    | Inspection date cannot be in the future                        |
| 9 | Stall Not Found                 | `404` Stall not found     | Stall existence is checked before inserting the record         |

Seeded officer credentials: `mary@email.com` / `Mary123!` &nbsp;|&nbsp; Seeded customer (for case 4): `alice@email.com` / `Alice123!`

## Feature 3 - Issue Hygiene Grade

**User Story:** *As a NEA Officer, I would like to issue a hygiene grade (A/B/C/D) to a stall after inspection, so that customers can see the food safety standard of each stall.*

**Endpoint under test:** `POST /hygiene-grades` — CRUD: **Create** (NEA officer only, JWT-protected)

**Business rule:** a grade can only be issued off an existing **completed** inspection that belongs to the **same stall**. Issuing a new grade retires the stall's previous active grade (transaction).

**Evidence:** Postman screenshots in [`screenshots/hayder-zikry/feature3-issue-hygiene-grade/`](./screenshots/hayder-zikry/feature3-issue-hygiene-grade/)

### Test cases

| # | Request                        | Expected                        | What it proves                                                   |
| - | ------------------------------ | ------------------------------- | ---------------------------------------------------------------- |
| 1 | Issue Grade - Success          | `201` + grade record          | Officer issues a grade off a completed inspection for that stall |
| 2 | Issue Grade - Lowercase Letter | `201` + grade record          | Grade letter is normalised to uppercase (Joi`.uppercase()`)    |
| 3 | No Token                       | `401` Unauthorized            | Endpoint requires authentication                                 |
| 4 | Customer Token (Wrong Role)    | `403` Forbidden               | Authorization is officer-only                                    |
| 5 | Invalid Grade Letter           | `400` validation error        | Grade must be one of A / B / C / D                               |
| 6 | Missing Grade                  | `400` validation error        | Joi requires`grade`                                            |
| 7 | Missing Inspection ID          | `400` validation error        | Joi requires`inspectionID`                                     |
| 8 | Inspection Not Completed       | `404` No completed inspection | A grade cannot be issued off a scheduled/incomplete inspection   |
| 9 | Inspection-Stall Mismatch      | `404` No completed inspection | The inspection must belong to the stall being graded             |

> **Cases 8 and 9** return the same `404` message but exercise different guards: **#8** the inspection exists but is only *scheduled* (not completed); **#9** the inspection is completed but belongs to a *different stall*.

Seeded officer credentials: `mary@email.com` / `Mary123!` &nbsp;|&nbsp; Seeded customer (for case 4): `alice@email.com` / `Alice123!`
Seeded completed inspections: `inspectionID 1` → stall 1, `inspectionID 4` → stall 5 (scheduled, not completed).
